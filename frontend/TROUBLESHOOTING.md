<a id="1"></a>
## 1. 가게 검색이 "장소 검색을 불러오지 못했어요"만 뜬다

**증상**
- 등록 모달에서 검색해도 결과가 안 나오고 안내 문구만 뜹니다.
- 브라우저 콘솔에는 오류가 없고, 네트워크 탭에만 `net::ERR_BLOCKED_BY_ORB` 가 보입니다.

**원인**

카카오 콘솔에 **사이트 도메인이 등록되지 않았습니다.** 등록되지 않은 origin에서
SDK를 부르면 카카오는 스크립트 대신 `401` JSON을 돌려줍니다:

```json
{"errorType":"AccessDeniedError","message":"domain mismatched! caller=http://localhost:5175"}
```

크롬은 `<script>` 자리에 온 JSON을 ORB(Opaque Response Blocking)로 차단하고,
브라우저는 `script.onerror` 만 알려줍니다. **그래서 화면에는 "못 불러왔다"는
정보밖에 남지 않습니다** — 진짜 원인(도메인 미등록)은 응답 본문 안에 있는데
그 본문을 자바스크립트로 읽을 수 없습니다.

**해결**

카카오 개발자 콘솔 > 내 애플리케이션 > **플랫폼 > Web > 사이트 도메인**에
개발 서버 주소를 **포트까지 정확히** 등록합니다.

```
http://localhost:5173
http://localhost:5174
```

`localhost` 와 `127.0.0.1` 은 서로 다른 도메인으로 취급되니 주의하세요.

**진단하는 법** — 브라우저로는 본문을 못 보지만 curl로는 보입니다:

```sh
KEY=$(grep '^VITE_KAKAO_JS_KEY=' .env | cut -d= -f2)
curl -s -H 'Referer: http://localhost:5173' \
  "https://dapi.kakao.com/v2/maps/sdk.js?appkey=$KEY&libraries=services&autoload=false" | head -c 200
# 정상  → window.kakao=window.kakao||{}...
# 미등록 → {"errorType":"AccessDeniedError","message":"domain mismatched! ..."}
```

Referer를 **빼면 200이 옵니다.** 카카오가 호출자를 식별 못 할 때는 그냥 내주기
때문인데, 이것 때문에 "curl은 되는데 브라우저만 안 된다"로 오진하기 쉽습니다.
반드시 Referer를 붙여서 확인하세요.

**재발 방지** — 배포할 때 운영 도메인(https)도 등록해야 합니다.

<a id="2"></a>
## 2. 한 번 실패한 뒤로는 검색이 영영 안 된다

**증상**

도메인을 등록하고 새로고침해도 검색이 계속 실패합니다. 지도는 뜨는데 검색만 안 되거나,
그 반대인 경우도 있습니다.

**원인**

`kakaoSdk.js` 버그였습니다. SDK 로딩에 실패하면 `sdkPromise` 캐시는 비웠지만
**실패한 `<script id="kakao-maps-sdk">` 태그가 DOM에 그대로 남아** 있었습니다.
다음 시도가 그 태그를 보고 "이미 받아 놨다"고 오판해 `window.kakao` 를 찾다가
곧바로 다시 실패합니다. 스크립트를 **다시 요청하지 않는** 게 핵심입니다.

지도와 검색이 같은 스크립트를 공유하기 때문에 실제로 항상 이 순서로 터집니다:
지도가 먼저 시도 → 실패 → 태그 남음 → 검색이 시도 → 태그 보고 오판 → 실패.

**해결** — 실패 시 캐시와 태그를 **둘 다** 비웁니다. [kakaoSdk.js](src/services/kakaoSdk.js) `fail()`:

```js
sdkPromise = null
document.getElementById(SCRIPT_ID)?.remove()
```

**재발 방지** — 회귀 테스트: `placeSearchApi.spec.js` > `한 번 실패해도 다음 시도에서 다시 받아온다`

<a id="3"></a>
## 3. 키를 넣었는데 인증이 안 된다

**증상** — 키를 `.env` 에 넣었는데도 카카오가 계속 거부합니다.

**원인** — 붙여넣을 때 **한 글자가 더 딸려왔습니다.** 카카오 앱 키는 정확히
**32자리 소문자 hex** 인데 33자였습니다. 눈으로는 구분이 안 됩니다.

**해결** — 값을 노출하지 않고 형식만 검사합니다:

```sh
python3 -c "
import re,pathlib
s=[l for l in pathlib.Path('.env').read_text().splitlines() if l.startswith('VITE_KAKAO_JS_KEY=')][0].split('=',1)[1].strip()
print('길이',len(s),'| 32자리 hex:',bool(re.fullmatch(r'[0-9a-f]{32}',s)))"
```

**주의** — 카카오 키는 두 종류이고 **형식이 똑같아서 눈으로 구분되지 않습니다.**

| | 용도 | 프론트엔드에 두어도 되나 |
|---|---|---|
| **JavaScript 키** | 브라우저에서 지도·장소 검색 | ✅ 단, 도메인 제한 필수 |
| **REST API 키** | 서버에서 호출 | ❌ 절대 안 됨 |

REST 키를 `VITE_` 로 넣으면 번들에 그대로 박혀 유출됩니다. `VITE_` 없이 넣으면
브라우저 코드가 읽지 못해 아무 일도 일어나지 않습니다. 둘 다 틀린 답입니다.

<a id="4"></a>
## 4. `npm run dev` 포트가 매번 바뀐다

**증상** — `Port 5173 is in use, trying another one...` 이 뜨고 5174, 5175로 옮겨 뜹니다.
그러면 [1번](#1)의 도메인 미등록으로 이어집니다.

**원인** — 이전에 띄운 dev 서버가 종료되지 않고 남아 있습니다. `npm run dev` 를
중단해도 자식 vite 프로세스가 살아남는 경우가 있습니다.

**해결**

```sh
lsof -nP -iTCP:5173 -sTCP:LISTEN     # 누가 쓰는지 확인
kill <PID>
npm run dev -- --port 5173           # 포트 고정
```

**주의** — 죽이기 전에 **내 프로젝트의 잔재가 맞는지** 확인하세요:

```sh
ps -o pid,lstart,command -p <PID>
lsof -a -p <PID> -d cwd | tail -1     # 작업 디렉터리 확인
```

<a id="5"></a>
## 5. 지도 타일에 `API KEY REQUIRED` 워터마크가 찍힌다

**증상** — `VITE_MAP_PROVIDER=carto` 로 바꾸면 타일마다 대각선 워터마크가 찍힙니다.

**원인** — CARTO가 정책을 바꿔 basemap에 API 키를 요구합니다. 예전에는 키 없이
쓸 수 있어서 그렇게 문서화돼 있었습니다.

**해결** — 현재는 **카카오 지도를 쓰므로 해당 없습니다.** OSM/CARTO 타일 설정은
제거했고, `VITE_MAP_PROVIDER` 환경 변수도 더 이상 쓰이지 않습니다.

**교훈** — "키 불필요"인 외부 서비스는 언제든 정책이 바뀝니다. 문서에 적어둔
전제는 시간이 지나면 틀릴 수 있습니다.

<a id="6"></a>
## 6. 에셋을 바꿨더니 테스트가 깨진다

**증상**

```
AssertionError: expected 'data:image/svg+xml,%3csvg%20xmlns=...' to contain 'heart-good'
```

**원인** — 에셋을 `public/` 에서 `src/assets/` 로 옮기고 `import` 로 바꾸자
**Vite가 4KB 미만 파일을 data URI로 인라인**했습니다. 하트 SVG는 172~335바이트라
전부 인라인됐고, `'/assets/heart-good.svg'` 같은 경로 문자열 비교가 전부 깨졌습니다.

4KB를 넘는 파일은 해시가 붙은 파일로 남습니다(`heart-good-a1b2c3.svg`). 즉
**파일 크기에 따라 결과 형태가 달라집니다.**

**해결** — 경로 모양을 검사하지 말고 **실제 규칙**을 검사하도록 바꿨습니다:

- 유닛: 세 등급의 아이콘이 서로 **다르다**는 것만 확인
- 유닛(컴포넌트): `HEART_GRADES[grade].asset` 과 직접 비교
- E2E: 핀의 하트가 **'하트 등급 안내' 카드의 같은 등급 하트와 같은 src** 인지 확인

**재발 방지** — 번들러가 정하는 경로를 테스트가 알고 있다고 가정하지 마세요.

<a id="7"></a>
## 7. '지도에서 위치 찍기'를 누르면 입력한 게 다 사라진다

**증상** — 장소명·주소를 입력하고 '지도에서 위치 찍기' 를 누른 뒤 지도를 클릭하면
좌표만 채워지고 **나머지 입력이 전부 비어 있습니다.**

**원인** — 이 흐름은 모달을 잠시 **닫았다가 다시 엽니다**(`formOpen = false → true`).
그런데 폼 초기화 로직이 `props.open` 변화를 보고 있어서, 다시 열릴 때 폼을
`blankForm()` 으로 갈아엎었습니다.

**해결** — `formSession` 카운터를 도입했습니다. **폼을 새로 열 때만** 증가하고,
위치 찍기로 접었다 펴는 것은 같은 세션이라 값이 그대로입니다. 초기화는 세션 변화만
보고, 포커스 이동만 `open` 변화를 봅니다.

**재발 방지** — E2E: `place-search.spec.js` > `지도에서 위치를 다시 찍으면 검색으로 고른 연결이 끊긴다`
(위치 찍기 후 장소명이 남아 있는지 함께 확인)

**교훈** — "열릴 때 초기화"는 모달이 **한 번만** 열린다고 가정한 것입니다.
중간에 접었다 펴는 흐름이 생기면 깨집니다.

<a id="8"></a>
## 8. 다시 빌드하면 저장해 둔 사진이 깨진다

**증상** — (사전에 예방한 문제) 시연용 사진을 `src/assets/` 에 두고 seed 데이터에
넣으면, 재빌드 후 localStorage에 저장된 이미지 URL이 404가 됩니다.

**원인** — `src/assets/` 의 파일은 빌드할 때마다 **내용 해시가 붙은 새 이름**이
됩니다. 그 URL이 localStorage에 저장돼 있으면 다음 빌드에서 가리키는 파일이 사라집니다.

**해결** — 저장되는 값이냐로 갈랐습니다:

| 위치 | 대상 | 이유 |
|---|---|---|
| `src/assets/` | 코드가 import 하는 에셋 | 해시로 캐시 안전 |
| `public/` | 파비콘, `samples/*.jpg` | **localStorage에 저장**되므로 고정 경로 필요 |

**재발 방지** — 사용자 데이터에 들어가는 경로는 `public/` 에 두세요.

<a id="9"></a>
## 9. 같은 가게인데 두 개로 등록된다

**증상** — 두 사람이 같은 가게를 각각 기록했는데 지도에 핀이 둘 뜨고 커플 점수가
갈라집니다. 반대로 같은 건물 2층 카페와 3층 술집이 **하나로 합쳐지기도** 합니다.

**원인** — 중복 판정이 `이름 완전일치 + 좌표 11m 이내` 였습니다. 문자열 비교라
`디어 모먼트` 와 `디어모먼트` 를 다른 가게로 보고, 좌표만 보므로 같은 건물의
다른 가게를 같은 가게로 봤습니다.

**해결** — 카카오 장소 ID(`providerPlaceId`)를 함께 저장하고 그것을 우선합니다.
판정은 [placeIdentity.js](src/utils/placeIdentity.js) 한 곳에서만 합니다:

1. 양쪽 다 공급자 ID가 있으면 **ID만** 비교 (좌표를 섞어 보지 않음)
2. 한쪽이라도 수기 입력이면 이름 + 좌표로 최선을 다해 판정

**재발 방지** — 등록할 때 **검색해서 고르는 것이 항상 낫습니다.** 직접 타이핑하면
`provider: 'manual'` 이 되어 예전과 같은 취약한 판정으로 돌아갑니다.
관련 테스트는 `placeRepository.spec.js` 의 공급자 ID 관련 항목들.

## 10. 지도에 확대/축소 버튼이 없다

**증상** — 지도에서 `+` / `-` 버튼이 사라졌습니다. 휠과 더블클릭으로는 확대가 됩니다.

**원인** — Leaflet에서 카카오 지도로 바꾸면서 생긴 회귀입니다. Leaflet은 확대/축소
컨트롤을 **기본으로 그려주지만 카카오 지도는 그리지 않습니다.** 명시적으로 붙여야 합니다.

동작 자체는 멀쩡하고 버튼만 없어서 테스트로도 안 잡혔습니다. 스크린샷을 비교하다 발견했습니다.

**해결** — [mapEngine.js](src/services/mapEngine.js) 의 카카오 엔진에서 붙입니다:

```js
map.addControl(new maps.ZoomControl(), maps.ControlPosition.TOPLEFT)
```

대체 지도(Leaflet)와 위치를 맞추려고 둘 다 왼쪽 위로 통일했습니다.

**교훈** — 지도 엔진을 갈아끼울 때는 **기본으로 제공되던 UI가 사라지지 않았는지**
확인하세요. 기능이 아니라 UI만 사라지면 테스트가 잡아주지 못합니다.

<a id="11"></a>
## 11. 배포하니 '내 위치'가 아무 반응이 없다

**증상** — 로컬에서는 되던 '내 위치' 버튼이 배포 후 권한 창조차 뜨지 않습니다.

**원인** — Geolocation API는 **보안 컨텍스트(https 또는 localhost)에서만** 동작합니다.
http로 배포하면 브라우저가 권한 창도 띄우지 않고 조용히 막습니다. `localhost` 는
예외라서 개발 중에는 멀쩡히 동작해 배포 전까지 드러나지 않습니다.

**해결** — https로 배포하세요. 코드에서는 호출 전에 `window.isSecureContext` 를 먼저
확인해 "https 연결에서만 현재 위치를 쓸 수 있어요" 라고 안내합니다
([geolocation.js](src/services/geolocation.js)). 그냥 호출하면 아무 콜백도 오지 않아
사용자는 버튼이 고장 난 줄 압니다.

**재발 방지** — 유닛: `geolocation.spec.js` > `https가 아니면 권한 창을 띄우기 전에 insecure로 알린다`

**참고** — 권한이 거부되어도 지도와 핀은 그대로 동작해야 합니다.
E2E: `my-location.spec.js` > `위치 권한이 없으면 안내하고 지도는 그대로 쓸 수 있다`
