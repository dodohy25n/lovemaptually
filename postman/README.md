# Postman API 전수 테스트

러브맵츄얼리 백엔드의 엔드포인트 **22개**를 성공 경로와 오류 경로로 모두 훑는 Postman 모음입니다.
요청 **58개**, 단언 **242개**로 이루어져 있습니다.

| 파일 | 무엇인가 |
| --- | --- |
| `lovemaptually.postman_collection.json` | 모음 본체입니다. Collection Format v2.1.0 입니다 |
| `lovemaptually.postman_environment.json` | 로컬 실행용 환경입니다. `baseUrl` 과 데모 계정, 그리고 실행 중 채워지는 빈 변수들이 들어 있습니다 |
| `테스트케이스.md` | 요청 하나에 한 줄씩 옮긴 표입니다. 발표 때 그대로 읽을 수 있습니다 |
| `verify-collection.py` | 서버를 켜지 않고 모음의 구조와 엔드포인트 덮개를 검사하는 스크립트입니다 |

---

## 무엇을 증명하는가

판정 기준은 `docs/API-명세.md` v3.4 의 **2장 엔드포인트 표**와 **4장 상태 코드 표**입니다.
"돌려 봤더니 200 이 나왔다"가 아니라 **명세가 약속한 코드가 그대로 나오는가**를 봅니다.

**1. 엔드포인트를 하나도 빠뜨리지 않았습니다.**
컨트롤러 8개에서 뽑은 (메서드, 경로) 22쌍을 모음이 전부 부릅니다. 이 대조는 사람 눈이 아니라
`verify-collection.py` 가 컨트롤러 소스를 직접 읽어서 합니다.

**2. 상태 코드를 코드별로 갈라 확인합니다.**
`200` `201` `202` `400` `401` `402` `403` `404` `409` `410` `422` 열한 가지가 모두 나옵니다.
같은 400 이라도 `VALIDATION_ERROR` 와 `INVALID_MONTH` 가 갈리는 자리, 같은 403 이라도
`NOT_GROUP_MEMBER` 와 `GROUP_ACCESS_DENIED` 가 갈리는 자리를 따로 둡니다.

**3. 상태 코드만 보지 않고 응답 봉투까지 봅니다.**
성공 응답은 `{status, message, data}` 이고 본문의 `status` 가 HTTP 상태 코드와 같아야 합니다.
오류 응답은 `{status, message, error:{code, details}}` 이고 **`error.code` 를 정확히 맞춥니다**.
화면이 이 값으로 분기하므로 코드가 바뀌면 프런트가 조용히 깨집니다. 그것을 여기서 잡습니다.

**4. 명세에만 적힌 규칙을 실제 응답에서 확인합니다.**

| 확인하는 규칙 | 어디서 |
| --- | --- |
| 담기만 하면 `label` 이 `null` 이고 리뷰가 붙어야 라벨이 생깁니다 | 우리 지도에 담기 201 |
| 리뷰 저장은 `tagStatus` 가 `COMPLETED` 이고 태그마다 사실(`fact`)과 바람(`want`)이 함께 붙습니다 | 리뷰 저장 201 |
| 남의 리뷰가 안 보이는 것은 권한이 아니라 상태라 403 이 아니라 200 입니다 | 장소의 그룹 리뷰 200 |
| 판정 분모인 `judgedMemberCount` 가 항목마다 함께 옵니다 | 그룹 취향 조회 200 |
| 접수만 하고 결과가 없어 201 이 아니라 202 이며 `status` 가 `PENDING` 입니다 | 추천 요청 202, 리포트 생성 요청 202 |
| Mock 결제 표시로 `paymentRef` 가 `MOCK-` 으로 시작합니다 | 구독 전환 201 |
| 402 는 "내 것인데 결제하면 열린다"라 403 과 다르며 `details[0].field` 가 `plan` 입니다 | FREE 그룹 리포트 요청 402 |
| 같은 달 재요청 409 의 `details` 에 기존 `reportId` 가 실려 화면이 그것을 엽니다 | 같은 달 재요청 409 |

## 두 번 돌려도 같은 결과가 나옵니다

**한 번 쓰고 버리는 모음이 아닙니다.** 발표 자리에서 다시 돌려도 앞선 실행이 남긴 데이터 때문에
빨간 줄이 뜨지 않도록 만들었습니다.

- **계정을 매번 새로 만듭니다.** 첫 요청의 사전 스크립트가 실행 시각으로 `pm-a-<시각>@lovemap.test`
  같은 이메일을 지어냅니다. 그래서 회원가입 201 이 언제 돌려도 201 입니다.
- **중복 409 는 이 실행이 방금 만든 데이터에서 끌어옵니다.** 이메일 중복 409 는 바로 앞 요청이 만든
  계정을, 리뷰 중복 409 는 리뷰 저장 201 의 응답에서 받아 둔 `visitedOn` 을 그대로 다시 보냅니다.
- **식별자를 하드코딩하지 않습니다.** `groupId` 는 그룹 생성 응답에서, `placeId` 는 장소 검색 결과에서,
  `inviteCode` 는 발급 응답에서 꺼내 컬렉션 변수에 담습니다. 시드 DB 의 번호가 달라져도 그대로 돕니다.
- **403 검사용 사용자를 따로 만듭니다.** 어느 그룹에도 속하지 않는 계정 하나를 만들어 두고 모든 403 을
  그 계정으로 때립니다. 소진된 코드로 참여를 시도하는 요청은 실패하므로 이 계정은 끝까지 그룹 밖에 남습니다.

**예외는 FREE 그룹 402 하나입니다.** 이 실행이 만든 그룹은 도중에 PREMIUM 으로 올라가므로 402 를 만들
수 없습니다. 그래서 이 한 건만 시드 데모 계정 `couple01a@lovemap.dev` 를 씁니다.
**이 계정은 프리미엄으로 전환한 적이 없어야 합니다.** 리허설 중에 올라가 버렸다면 402 대신 다른 코드가
오는데, 그때는 실패가 아니라 "건너뜀"으로 알리고 콘솔에 사유를 남깁니다. DB 를 비우고
`scripts/seed-demo.sh` 를 다시 돌리면 402 가 되살아납니다.

## Postman 앱에서 돌리기

1. Postman 을 열고 **Import** 를 눌러 `lovemaptually.postman_collection.json` 과
   `lovemaptually.postman_environment.json` **두 파일을 함께** 넣습니다.
2. 오른쪽 위 환경 선택 상자에서 **러브맵츄얼리 로컬**을 고릅니다.
   환경을 고르지 않으면 `baseUrl` 이 비어 첫 요청부터 실패합니다.
3. 왼쪽 목록에서 모음 이름 오른쪽의 **...** 를 눌러 **Run collection** 을 고릅니다.
4. 폴더 순서를 그대로 두고 **Run 러브맵츄얼리 API 전수 테스트**를 누릅니다.
   **요청 순서를 바꾸면 안 됩니다.** 앞 요청이 저장한 변수를 뒤 요청이 쓰기 때문입니다.
5. 결과 화면의 초록 줄이 통과한 단언입니다. 242개가 모두 초록이면 전수 통과입니다.

폴더 하나만 보고 싶으면 Runner 에서 그 폴더만 골라 돌릴 수 있지만, 앞 폴더가 만든 변수가 없으면
실패합니다. 처음에는 모음 전체를 한 번 돌린 뒤에 폴더 단위로 다시 돌리십시오.

## 터미널에서 돌리기

Postman 앱 없이 같은 모음을 그대로 돌립니다. 발표 화면에 결과 표를 띄우기에 이쪽이 낫습니다.

```
npx newman run postman/lovemaptually.postman_collection.json -e postman/lovemaptually.postman_environment.json
```

리포트 파일로 남기려면 이렇게 합니다.

```
npx newman run postman/lovemaptually.postman_collection.json \
  -e postman/lovemaptually.postman_environment.json \
  --reporters cli,json --reporter-json-export postman/newman-result.json
```

`newman` 은 요청 하나라도 단언이 깨지면 종료 코드 1 을 내므로 CI 에 그대로 걸 수 있습니다.

## 서버 없이 모음 자체를 검사하기

```
python3 postman/verify-collection.py
```

백엔드를 켜지 않아도 돌아갑니다. 하는 일은 네 가지입니다.

1. 모음 JSON 이 읽히는지, 요청마다 이름, 메서드, URL, 설명, 테스트 스크립트가 있는지 봅니다.
2. `backend` 의 컨트롤러 소스를 직접 읽어 (메서드, 경로) 목록을 뽑고, 모음이 그 전부를 덮는지 맞춥니다.
3. 요청 수, 단언 수, 상태 코드 분포, 오류 코드 분포를 셉니다.
4. `node` 가 있으면 모든 스크립트가 문법에 맞는 자바스크립트인지까지 봅니다.

덮지 못한 엔드포인트가 하나라도 있으면 종료 코드 1 입니다.
**컨트롤러에 엔드포인트를 새로 추가하면 이 검사가 먼저 깨집니다.** 모음이 명세를 따라가지 못하는 것을
사람이 눈으로 세는 대신 스크립트가 잡습니다.

## 기존 `scripts/contract-check.sh` 와의 관계

`scripts/contract-check.sh` 는 상태 코드 조합 31개를 curl 로 때리는 셸 스크립트입니다.
이 모음은 그것이 보던 조합을 모두 포함하고, 다음을 더 봅니다.

- **셸 스크립트가 건너뛰던 성공 경로**를 채웠습니다. 회원가입 201, 그룹 생성 201, 초대 발급 201,
  코드 확인 200, 그룹 참여 201, 장소 상세 200, 지도에 담기 201, 핀 상세 200, 리뷰 저장 201,
  리뷰 조회 200, 추천 결과 조회 200, 구독 전환 201, 리포트 생성 202, 리포트 단건 조회 200 이
  새로 들어왔습니다. 셸 스크립트의 31개 조합은 하나도 빠짐없이 그대로 들어 있습니다.
- **상태 코드만이 아니라 `error.code` 와 응답 본문**을 함께 확인합니다. 셸 스크립트는 HTTP 코드만 봅니다.
- **시드 계정에 기대지 않습니다.** 셸 스크립트는 `dohyeon@lovemap.dev` 의 기존 리뷰 날짜를 찾아
  중복 409 를 만들지만, 이 모음은 자기가 만든 리뷰로 만듭니다.

둘 다 남겨 둡니다. 셸 스크립트는 배포 직후 30초 안에 돌리는 빠른 확인이고,
이 모음은 화면에 띄워 보여 주는 전수 테스트입니다.

## 아는 한계

- **추천 결과와 리포트 본문의 내용은 검사하지 않습니다.** 순위와 문장은 데이터에 따라 달라지므로
  `status`, `cfWeight` 범위, `content` 의 존재 여부 같은 계약만 봅니다.
- **`500` 과 `502` 는 요청으로 만들지 않습니다.** 처리하지 못한 예외의 안전망과 외부 지도 API 오류라
  정상 요청으로 재현할 수 없습니다. `502 MAP_PROVIDER_ERROR` 는 명세도 R1 의 자리로 남겨 두었습니다.
- **`COUPLE_GROUP_FULL`(409)과 `GROUP_MEMBER_ALREADY_EXISTS`(409)** 는 이 모음이 만들지 않습니다.
  두 사람이 찬 커플 그룹에 세 번째 코드를 발급해야 하는데, 발급한 코드가 소진되면 그전에 410 이
  먼저 걸립니다. 만들려면 초대 코드를 두 개 발급하는 단계를 더 넣어야 해서 남겨 두었습니다.
- **`PLACE_REQUIRED`(400), `INVALID_LABEL`(400), `GROUP_PLACE_NOT_FOUND`(404),
  `GROUP_NOT_FOUND`(404), `INVALID_REQUEST_BODY`(400), `API_NOT_FOUND`(404)** 도 같은 이유로
  뺐습니다. 엔드포인트 자체는 다른 요청이 이미 덮고 있어 전수 덮개에는 구멍이 없습니다.
