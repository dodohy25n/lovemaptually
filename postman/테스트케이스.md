# 테스트 케이스 목록

`postman/lovemaptually.postman_collection.json` 의 요청을 한 줄씩 옮긴 표입니다. 순서와 이름이 모음과 같으므로 Runner 결과 화면과 나란히 놓고 볼 수 있습니다.

판정 기준은 API 명세 v3.4 의 2장 엔드포인트 표와 4장 상태 코드 표입니다. 요청마다 HTTP 상태 코드와 응답 봉투를 함께 확인하고, 오류 응답은 `error.code` 까지 정확히 맞춥니다. 기대 오류 코드 칸이 비어 있으면 성공 응답이라 `{status, message, data}` 봉투를 확인한다는 뜻입니다.

## 1. 인증

명세 2장 인증 표. 회원가입과 로그인, 그리고 토큰 없는 접근이 401 로 막히는지까지 봅니다.

| 번호 | 대상 엔드포인트 | 무엇을 검증하는가 | 기대 상태 코드 | 기대 오류 코드 |
| ---: | --- | --- | ---: | --- |
| 1 | `POST /api/auth/signup` | 새 계정이 저장되고 accessToken 과 tokenType 이 함께 내려옵니다 | `201` | - |
| 2 | `POST /api/auth/signup` | 같은 이메일로 다시 가입하면 users.email UNIQUE 제약에서 막힙니다 | `409` | `EMAIL_ALREADY_EXISTS` |
| 3 | `POST /api/auth/signup` | 이메일 형식, 비밀번호 길이, 닉네임 누락 세 가지가 details 3건으로 옵니다 | `400` | `VALIDATION_ERROR` |
| 4 | `POST /api/auth/signup` | 초대를 받을 두 번째 사용자를 만듭니다 | `201` | - |
| 5 | `POST /api/auth/signup` | 어느 그룹에도 속하지 않아 403 검사에 쓸 사용자를 만듭니다 | `201` | - |
| 6 | `POST /api/auth/login` | 저장된 BCrypt 해시로 검증하고 토큰과 만료 시간을 내려줍니다 | `200` | - |
| 7 | `POST /api/auth/login` | 어느 쪽이 틀렸는지 밝히지 않고 인증 실패로만 답합니다 | `401` | `AUTHENTICATION_FAILED` |
| 8 | `GET /api/groups/me` | Authorization 헤더가 없으면 보호된 자원이 열리지 않습니다 | `401` | `UNAUTHORIZED` |
